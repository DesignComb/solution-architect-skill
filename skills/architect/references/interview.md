# 階段 1 題庫：需求訪談

一次問一到兩題。選擇題用 AskUserQuestion；追問用對話。題目順序可以依對話自然調整，但**輪到寫文件時，每個區塊都要有答案**。

## Q1. 一句話定位

「這個東西是在幫**誰**解決**什麼事**？」

- 講不出來就用追問拆解：「現在沒有它的時候，那些人都怎麼辦？」
- 追到能寫成「幫〔某群人〕把〔某件事〕從〔現況〕變成〔更好的樣子〕」為止。
- ⚠️ 使用者若一開口就是技術方案（「我要做一個用 AI 的平台」），把他拉回問題本身：「先不管怎麼做——是誰、遇到什麼麻煩？」

## Q2. 產品形態（選擇題）

「它比較像下面哪一種？」

| 選項 | 例子 | 對後面的意義 |
|------|------|--------------|
| 內容展示 | 官網、作品集、部落格、活動頁 | 多半可以純靜態、幾乎零成本 |
| 工具 | 計算機、產生器、查詢器 | 看要不要存資料，可能不用後端 |
| 交易／預約 | 電商、課程報名、場地預約 | 一定有金流、庫存/時段、通知 |
| 管理系統 | 內部工具、會員名單、進銷存 | 登入 + 權限 + 表格 CRUD 為主 |

社群互動（留言、追蹤、配對）與其他形態用「Other」讓使用者自己描述。混合形態就記下主形態 + 副形態。

## Q3. 使用者是誰、有多少（選擇題可拆兩題）

1. 「用的人是？」——自己/親友、特定小圈子（社團、公司同事）、你的客戶、公開大眾。
2. 「頭一年，樂觀估計多少人會用？」——< 100、100–1,000、1,000–10,000、更多。
   - 註：這題是抓數量級用的，不用準。**絕大多數專案終其一生 < 10,000 人**，免費額度就夠；使用者若選「更多」，追問憑什麼（已有粉絲？公司既有客戶？），沒有具體來源就當 1,000–10,000 規劃並在建議書註明升級路徑。

## Q4. 使用情境（決定 Web / PWA / APP 的證據，先記錄、不判斷）

逐項問，答案照實記：

1. 「使用的人主要用**手機**還是**電腦**開它？」（手機為主 / 電腦為主 / 都有）
2. 「需不需要**主動通知**使用者？」（例如：訂單來了、有人回覆了）——要的話，追問「用 Email 或 LINE 通知可以嗎，還是一定要手機推播？」
3. 「會不會用到手機的硬體？」——相機掃碼、GPS 定位、藍牙、NFC 感應。逐項確認，並問清楚是「拍張照上傳」（Web 就能做）還是「持續在背景定位」（要 APP）這種程度差異。
4. 「沒有網路的時候需不需要能用？」（完全不用 / 看過的東西能再看就好 / 要能離線操作再同步）
5. 「一定要在 App Store / Google Play 上架嗎？為什麼？」——常見真實理由只有兩種：老闆/客戶指定、目標族群習慣在商店搜尋。其他多半是想像。

## Q5. 資料與關聯

1. 「要記錄哪些東西？」列出主要資料（例如：商品、訂單、會員）。
2. 每種資料抓 3–5 個關鍵欄位就好（細節留給實作階段）。
3. 「這些資料之間有關係嗎？」（訂單屬於某個會員這種程度即可）
4. 「有沒有現成的資料要搬進來？」（Excel、Google 表單、舊系統）

## Q6. 登入與角色

- 「需要知道**是誰**在用嗎？」不需要登入是完全正當的答案，不要預設要登入。
- 要登入的話：「用的人願意為這個東西多記一組密碼嗎？」→ 傾向社群登入（Google/LINE）還是 Email。
- 「有沒有不同身分看到不同東西？」（管理員 vs 一般使用者，夠用就好）

## Q7. 金流與法遵（有交易才問）

1. 「怎麼收錢？」一次性付款 / 訂閱 / 到現場再付（只需要預約不需要金流）。
2. 「收款方是個人還是公司行號？」——影響金流服務申請與電子發票義務，照實記錄。
3. 「主要收台灣的錢還是海外的錢？」——決定金流服務選擇，記錄即可。
4. 敏感資料自查：會不會碰到身分證字號、病歷/健康、未成年人資料？有就記下來，建議書要加註法遵段落。

## Q8. 成功長什麼樣子

「三個月後，怎樣算成功？」抓一個可以數的指標（每週有 20 個人用、收到第一筆訂單、同事不再用 Excel 傳來傳去）。這個指標會寫進建議書的路線圖當檢查點。

## Q9. 長什麼樣子（風格三選一）

「你希望它給人什麼感覺？」用 AskUserQuestion 出三選一：**俐落**（乾淨專業像工具）、**雜誌**（有質感像刊物）、**溫暖**（圓潤親切有生活感）。依產品形態把預設推薦放第一個選項；使用者自己描述其他感覺也照收。選項描述與後續規格見 [style-presets.md](style-presets.md)——**問的時候只講感覺，不丟元件庫或字體名字**。

## 產出格式：`solution/01-requirements.md`

```markdown
# 需求摘要：〈專案名（沒有就先用一句話定位）〉

- **一句話定位**：幫〔誰〕把〔什麼事〕從〔現況〕變成〔更好〕
- **形態**：主形態（＋副形態）
- **使用者與規模**：誰在用；頭一年估計數量級
- **使用情境**：
  - 裝置：手機為主／電腦為主／都有
  - 通知：不用／Email 或 LINE 即可／需要手機推播（原因）
  - 硬體：無／相機（程度）／GPS（程度）／藍牙／NFC
  - 離線：不用／唯讀／可離線操作
  - 上架商店：不用／要（原因）
- **資料**：每種資料一行（名稱＋關鍵欄位＋關聯）
- **既有資料搬遷**：無／有（來源）
- **登入**：不用／要（方式、角色）
- **金流**：無／有（方式、個人或公司、台灣或海外）
- **敏感資料**：無／有（哪種）
- **外觀方向**：俐落／雜誌／溫暖（＋使用者補充的形容詞）
- **三個月成功指標**：〈可以數的一句話〉
- **訪談留白**：使用者不確定、之後要再確認的事
```

寫完給使用者看摘要，確認後說：「需求記好了。接下來盤點你手上的資源，大概 5 分鐘。」
