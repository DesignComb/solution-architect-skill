# 白話對照表（訪談與建議書共用）

技術名詞第一次出現時，用這張表的白話講法。原則：**每一句都要唸得順**，比喻用「開一間店」貫穿；同一個詞全程用同一種講法，不要一下說「後端」一下說「伺服器端」。

## 一間店的比喻（教學網站同款，保持一致）

| 技術名詞 | 白話講法 |
|----------|----------|
| 前端 | 客人看到、摸到的那一層，就像店面 |
| 後端 | 在背後處理事情的邏輯，就像廚房 |
| 資料庫 | 存放所有資料的地方，就像倉庫 |
| API | 前後場溝通用的固定格式，就像點餐單 |
| 網域 | 你的網址，就像店的地址 |
| 部署 | 把做好的東西放上網路，就像正式開店 |
| 雲端 | 租來的別人家電腦，機器壞了房東修 |
| 主機／伺服器 | 一台一直開著、負責服務大家的電腦 |

## 常用詞

| 技術名詞 | 白話講法 |
|----------|----------|
| PWA | 裝在手機上的網頁（教學內容一律用這個講法，不用縮寫） |
| 原生 APP | 從商店下載安裝的那種 APP |
| 跨平台 | 寫一次，Apple 和 Android 都能用 |
| SEO | 讓 Google 搜得到你 |
| CDN | 把網頁放到離使用者近的地方，開起來比較快 |
| HTTPS | 網址列的鎖頭，表示傳輸有加密 |
| SSL 憑證 | 讓鎖頭出現的證書，要定期換新 |
| DNS | 把網址翻譯成機器位置的通訊錄 |
| 預設網址（平台子網域） | 平台免費送的網址，像「你的名字.netlify.app」，後半段是平台的招牌，換平台就作廢 |
| 自訂網域 | 把自己買的網址接到平台上；主要幾家的免費層本來就能綁，但條款管的是用途不是網址 |
| 冷啟動／休眠 | 免費方案沒人來就關機，第一位訪客要等它開機，不是壞掉 |
| 金鑰（API key） | 服務發給你的鑰匙，拿到就能動用你的帳號和錢 |
| 公開金鑰（publishable key，舊名 anon key） | 設計成可以放在網頁裡的鑰匙，權限很低，安全靠門禁規則把關 |
| 秘密金鑰（secret key，舊名 service_role key） | 繞過所有門禁的萬能鑰匙，只能放在你控制的伺服器上 |
| RLS（門禁規則） | 資料庫裡一列一列的規則，決定誰能看到、誰能修改哪些資料 |
| token（通行證） | 登入成功後拿到的臨時通行證，過期就要重新登入 |
| 快取（cache） | 存在你電腦或中繼站的網頁影本，開起來快，但可能是舊的 |
| 本機／測試環境 | 只有你看得到的樣品屋，資料跟正式的分開 |
| 正式環境 | 有網址、大家都看得到的真店面 |
| migration（施工紀錄） | 每次改資料表結構都留一張有編號的施工單，能重演也能退回 |
| OAuth（借櫃台登入） | 「用 Google 登入」這種做法，把驗身分交給別家櫃台，網站拿不到你的密碼 |
| context（工作桌） | AI 一次能記住的對話量，桌子滿了就會開始忘東西 |
| 環境變數 | 放金鑰這類秘密的抽屜，跟程式碼分開收 |
| SDK | 官方做好的零件包，照著接就能用 |
| MCP | 讓 AI 直接操作某個服務的接頭 |
| CLI | 用打字下指令的操作方式 |
| repo | 程式碼保險箱：存程式碼的資料夾，兼歷史紀錄簿 |
| 版本控制 | 每次改動都留底，隨時可以回到之前的樣子 |
| 備份 | 把資料多存一份在別的地方 |
| 還原 | 把備份拿出來，真的變回原樣才算數 |
| 回滾 | 出事時退回上一個正常版本 |
| 登入／驗證 | 確認現在操作的人是誰 |
| 權限 | 誰能看什麼、改什麼的規則 |
| 推播 | APP 主動跳到手機上的通知 |
| webhook | 事情發生時，服務主動通知你的系統一聲 |
| 串接 | 讓兩個服務互相講話 |
| 免費層／免費額度 | 服務免費送的用量，超過才收錢 |
| 託管／全託管 | 機器和維運都交給平台顧，你只管內容 |
| 開源 | 程式碼公開，任何人都能看、能用 |

## 用法

- 訪談時：只用白話欄的講法問問題，技術名詞不出現。
- 建議書裡：白話為主，技術名詞放括號附在後面，例如「資料庫（PostgreSQL，一種最通用的倉庫）」。
- 表上沒有的詞：現場造一句同等白話的解釋，並考慮補進這張表。
