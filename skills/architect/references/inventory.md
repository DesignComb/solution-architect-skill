# 階段 2 題庫：資源盤點

目的：架構建議必須「買得起、養得動」。同一個需求，資源不同，正確答案就不同——這一階段就是在找出那些會改變答案的事實。一樣一次問一到兩題。

## R1. 人：誰來做？

「這個東西誰來做？」

| 情況 | 對建議書的意義 |
|------|----------------|
| 我自己＋AI 助手（不會寫程式） | 選「AI 最熟、範例最多」的主流技術；避免小眾框架；part 數越少越好 |
| 我自己（會寫程式） | 追問熟什麼語言/框架——**熟的技術優先於「最佳」技術** |
| 有朋友/同事幫忙 | 問那個人熟什麼，以他為準 |
| 找外包 | 建議書要多一節「發包規格與驗收清單」，選市場上接案人多的主流技術 |

追問（自己做的話）：「有沒有在用 Claude 或其他 AI 寫程式的工具？」——有 AI 助手，「不會寫程式」不再是擋路的理由，但更該選主流技術（AI 訓練資料多、寫得對的機率高）。

## R2. 錢：兩個數字

1. 「每個月固定花在這上面，多少以內你不會心痛？」——0 元也是正當答案。（區間：$0 / 台幣幾百 / 台幣一兩千 / 更多）
2. 「一次性的錢呢？」（網域一年幾百塊台幣、Apple 開發者帳號一年 US$99 這種）

⚠️ 提醒使用者：真正貴的通常不是服務費，是**人的時間**。建議書的成本表會把「每月維運時間」也列進去。

## R3. 時間

1. 「多快要能給人用？」（這週末就要 / 一個月內 / 一季內 / 不急）
2. 「每週大概能投入幾小時？」

時間紅線：**趕時間 = 砍範圍，不是加人加工具。** 這週末就要的東西，建議書只能給「現成服務 + 最小自建」的組合。

## R4. 已有資源（逐項快問）

- 網域：「有沒有買過網域？」
- 帳號：GitHub？Google 帳號？Apple 開發者帳號？
- 現成資料：Excel、Google 表單/試算表、舊系統（階段 1 問過就不重問）
- 別人給的：公司/學校有沒有提供主機、資料庫、G Suite？有沒有學生方案（GitHub Student Pack）？
- 訂閱中的：已經在付錢的服務（Claude Pro、Notion、Canva…）——已付費的工具優先用好用滿

## R5. 維運底線

1. 「上線之後，東西半夜壞了，誰處理？」（我自己 / 沒有人——那就要選「幾乎不會壞」的架構）
2. 「你願意每個月花多少時間顧它？」（幾乎不想管 / 每週一兩小時 / 這就是我的主業）

「幾乎不想管」→ 全託管服務（PaaS/BaaS），**明確排除自租 VPS 自己裝**，就算 VPS 比較便宜也一樣——省下的錢會用維運時間加倍還回去。

## R6. 底線確認（一題）

「如果免費額度哪天不夠用了，你比較能接受哪個？」

- 開始付月費（大約台幣幾百到一千）
- 花一個週末搬家到便宜的方案
- 到時候再說（→ 建議書照「開始付月費」規劃，並附搬家逃生路線）

---

## 產出格式：`solution/02-resources.md`

```markdown
# 資源盤點：〈專案名〉

- **人**：誰做、技術背景、AI 助手有無
- **月預算**：$X 以內；**一次性預算**：$Y 以內
- **時程**：什麼時候要能用；每週可投入 N 小時
- **已有資源**：網域／帳號／資料／公司或學校提供／訂閱中
- **維運**：誰顧、每月願意花的時間、託管偏好（全託管／可自管）
- **額度爆掉時**：付費／搬家／未定（照付費規劃）
```

寫完摘要回放確認，然後說：「資源盤好了。接下來我不會再問問題——給我一點時間，把架構建議書寫出來。」
